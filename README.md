# clxcpp

A dependency-free C++17 library + CLI for parsing **Clinx chemiluminescence
instrument `.clx` files** — the native capture format produced by the imager in
the lab. A `.clx` file bundles acquisition metadata (sample name, capture time,
exposure) together with the **raw 16-bit fluorescence and bright-field images**.

This is a C++ port of the Python `clxparser` project,
kept **pixel-identical** to it: exported TIFFs and 16-bit PNGs carry exactly the
raw 16-bit pixels from the `.clx` capture, and the 8-bit preview path matches
the Python implementation's numpy-based percentile scaling byte-for-byte.

## Features

- **Parse** `.clx` metadata: magic, capture time (OLE date), exposure, sample
  name, software id, build date, trailer statistics.
- **Export** each embedded image as a **TIFF** (pixel-identical to the
  instrument's own export) or a lossless **16-bit grayscale PNG**.
- **Preview** images as **8-bit auto-scaled PNGs** using percentile stretching.
- **JSON** metadata sidecar via `to_json()`.
- **CLI**: `info`, `extract`, `preview` — mirroring `python -m clxparser`.

No external dependencies beyond a vendored copy of
[miniz](https://github.com/richgel999/miniz) (public domain) for PNG deflate and
CRC32.

## Building

Requires CMake and a C++17 compiler (MSVC 2022 or GCC/Clang).

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

## Command-line

```
build\clx.exe info   capture.clx                 # show metadata
build\clx.exe extract capture.clx --outdir out   # tiff+png+json
build\clx.exe extract capture.clx --formats tiff,json
build\clx.exe preview capture.clx --image 1 --out preview.png
```

`extract` writes, per image, the instrument-style names
`<stem>_<i>_16bit.tif` / `_16bit.png` plus a `_metadata.json` sidecar
(`--preview` adds auto-scaled 8-bit previews).

## Library quickstart

```cpp
#include <clxcpp/clx.hpp>

clxcpp::clx_file f = clxcpp::load("capture.clx");

f.sample_name;        // "Samp1_20260804_161544"
f.capture_time;       // optional<datetime>
f.exposure_ms;        // 6946
f.image_count();      // 2

for (const auto& img : f.images) {
  img.width(); img.height(); img.bits_per_sample();
  auto tiff = img.to_tiff_bytes();          // pixel-identical to instrument export
  auto png  = img.to_png_bytes();           // lossless 16-bit grayscale PNG
  auto preview = img.preview_png_bytes();   // 8-bit auto-scaled
}

std::cout << f.summary();
std::cout << f.to_json();                   // JSON-serializable metadata
```

## Tests

```
ctest --test-dir build --output-on-failure
```

The suite checks metadata, dimensions, exposure and capture time against the
real samples, asserts the embedded pixels and exported TIFFs carry the same
pixel data as the instrument's `.tif` files, round-trips PNGs with a
self-contained decoder, and compares the `summary()`, `to_json()`, 16-bit PNG
and preview outputs byte-for-byte against reference files generated by the
Python `clxparser` implementation.

## Project layout

```
include/clxcpp/clx.hpp   public API (load, clx_file, clx_image, encoders)
src/core.cpp             parser: header, descriptor scan, metadata, helpers
src/tiff.cpp             TIFF writer (matches instrument export pixels)
src/png.cpp              PNG writer (16-bit lossless + 8-bit preview)
src/export.cpp           bulk export + metadata JSON
src/main.cpp             CLI (info / extract / preview)
third_party/             vendored miniz (public domain) for deflate + CRC32
docs/                    format specification (EN + zh-CN)
tests/                   CTest suite incl. pixel-identity vs real exports
```

## Notes & caveats

- **Reverse-engineered format.** This library was developed by reverse
  engineering a small number of `.clx` files output by a single device. It is
  **not guaranteed** to parse every `.clx` file produced by all Clinx products.
  Validate against your own files first.
- Only raw, uncompressed 16-bit (and 8/32-bit) images are supported.
- Channel identification (`brightfield` vs `fluorescence`) is a heuristic based
  on mean intensity and should not be trusted for downstream decisions if your
  acquisition settings vary.
- `to_json()` embeds the input path verbatim (like the Python implementation).
